# รายรับรายจ่ายบนโทรศัพท์และการซิงก์

Taxly ใช้เว็บแอปติดหน้าจอโฮม (PWA) สำหรับ iPhone/Android และ Supabase สำหรับข้อมูลออนไลน์ คอมพิวเตอร์ไม่ต้องเปิดค้างไว้ หลังตั้งค่าบริการแล้ว เข้าบัญชีเดียวกันบนมือถือและในแอปคอมพิวเตอร์ รายการจะอัปเดตเมื่อออนไลน์

## ตั้งโปรเจกต์ใหม่สำหรับ Taxly

1. เข้า [Supabase Dashboard](https://supabase.com/dashboard) ด้วยบัญชีของคุณ สร้างโปรเจกต์ชื่อ `Taxly` ในองค์กรของคุณ เลือกภูมิภาคใกล้ผู้ใช้ ตั้งรหัสผ่านฐานข้อมูลในหน้า Supabase เก็บไว้ใน password manager ไม่ต้องส่งรหัสผ่านให้แอปหรือในแชต
2. รอฐานข้อมูลพร้อม แล้วเปิด SQL Editor รัน [migration ซิงก์](../supabase/migrations/202610310001_ledger_sync.sql) แล้วตามด้วย [migration ซิงก์ภาษี](../supabase/migrations/202611010001_tax_sync.sql) **อย่างละครั้งในโปรเจกต์ใหม่** อย่ารันไฟล์ทดสอบในโปรเจกต์จริง ตารางทั้งสามเปิด Row Level Security และแอปเขียนผ่าน RPC ที่ตรวจข้อมูลและรุ่นก่อนบันทึกเท่านั้น
3. คัดลอก Project URL และ **publishable key** จาก Connect/API Keys ของโปรเจกต์ ใช้ `anon` key รุ่นเก่าได้เช่นกัน ห้ามใช้ `sb_secret_` หรือ `service_role` key ในตัวแอป เว็บ หรือค่า `VITE_*`
4. ตรวจว่า `taxly_sync_heads` อยู่ใน publication `supabase_realtime` migration จะเพิ่มตารางนี้เมื่อ publication มีอยู่แล้ว หากต้องเพิ่มภายหลัง รัน `ALTER PUBLICATION supabase_realtime ADD TABLE public.taxly_sync_heads;` เพียงครั้งเดียว
5. เปิด Email provider ใน Authentication เปิด Confirm email และกำหนดความยาวรหัสผ่านอย่างน้อย 12 ตัวอักษร แอปมีเข้าสู่ระบบ สมัครบัญชี และรีเซ็ตรหัสผ่านผ่านอีเมล ต้องตั้ง SMTP ที่ส่งอีเมลให้ผู้ใช้ได้ก่อนใช้งานจริง ดู [คู่มือ SMTP](https://supabase.com/docs/guides/auth/auth-smtp)

## นำเว็บมือถือขึ้นโฮสต์ HTTPS

เว็บต้องให้บริการที่รากโดเมน `/` และเรียก `sw.js`, `manifest.webmanifest`, `assets/*` ได้ ใช้โฮสต์ไฟล์สแตติกที่รองรับ HTTPS เช่น Vercel เลือก Root Directory เป็น `apps/desktop` ใช้ `npm run build` และ Output Directory เป็น `dist` มี `vercel.json` สำหรับ header ความปลอดภัยและไม่แคชไฟล์ service worker แบบถาวร

ตั้ง environment variables ในโฮสต์ **ก่อน build** โดยใช้ค่าจากโปรเจกต์ใหม่:

```dotenv
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_YOUR_PUBLIC_KEY
VITE_TAXLY_WEB_URL=https://YOUR_TAXLY_HOST
```

ค่าเหล่านี้เป็นข้อมูลสาธารณะที่ถูกใส่ใน JavaScript ฝั่งผู้ใช้ การป้องกันข้อมูลอยู่ที่บัญชีผู้ใช้และ RLS ห้ามใส่รหัสผ่านฐานข้อมูลหรือ secret key

หลังทราบ URL จริง ตั้ง Authentication → URL Configuration: Site URL เป็น URL เว็บ Taxly และเพิ่ม URL เดียวกันใน Redirect URLs เพื่อให้ยืนยันอีเมล/กู้รหัสผ่านกลับมาที่แอป ดู [คู่มือ redirect URLs](https://supabase.com/docs/guides/auth/redirect-urls) เมื่อตั้ง `VITE_TAXLY_WEB_URL` ใหม่ต้อง build/deploy เว็บและ build แอปคอมพิวเตอร์อีกครั้ง หรือกรอกที่อยู่เว็บในหน้าการเชื่อมต่อของแอปคอม

## เริ่มใช้งาน

1. บนคอมพิวเตอร์ เปิด **รายรับรายจ่าย → บัญชีและซิงก์** หาก build ยังไม่มีค่าบริการ ให้กรอก Project URL, publishable key และ URL เว็บมือถือ สมัครหรือเข้าบัญชี แล้วกด **เริ่มซิงก์กับบัญชีนี้** เพื่อยืนยันการส่งรายรับรายจ่ายในเครื่อง
2. บนโทรศัพท์ เปิด URL เว็บ HTTPS ใน Safari/Chrome แล้วเข้าบัญชีเดียวกัน ไม่ต้องเปิดเครื่องคอมค้างไว้ เมื่อ build เว็บมี environment variables แล้ว ไม่ต้องกรอกค่าบริการในโทรศัพท์
3. iPhone: แชร์ → เพิ่มไปยังหน้าจอโฮม Android: เมนู Chrome → เพิ่มลงในหน้าจอหลัก เปิดออนไลน์อย่างน้อยหนึ่งครั้งให้ดาวน์โหลดส่วนแอปและฟอนต์ครบก่อนใช้ออฟไลน์
4. เพิ่ม แก้ไข ลบรายการ จัดหมวด หรือนำเข้า CSV ได้จากโทรศัพท์ ป้ายด้านบนแสดงกำลังซิงก์/ซิงก์แล้ว/รอส่ง หากสองเครื่องแก้รายการเดียวกันต่างกัน ให้เลือกข้อมูลในเครื่องหรือออนไลน์ในหน้าซิงก์ก่อนทำต่อ

## ขอบเขตข้อมูลและการกู้คืน

- ซิงก์หมวดหมู่ รายรับรายจ่าย ตัวเลือกที่ติ๊กให้นับเป็นรายได้ภาษี และข้อมูลภาษี ได้แก่ คำตอบเรื่องสิทธิ์และขอบเขตของแต่ละปี การยืนยันว่ารายได้ครบ รายได้ในหน้า "รายได้ของฉัน" และประกันสังคมรายเดือน ไม่ส่งประวัติผลคำนวณหรือแบบร่างที่ยังตอบไม่เสร็จขึ้นคลาวด์
- ต้องรัน [migration ซิงก์ภาษี](../supabase/migrations/202611010001_tax_sync.sql) ต่อจาก migration แรกหนึ่งครั้ง แอปรุ่นเก่าที่ไม่รู้จักข้อมูลภาษีจะส่งข้อมูลไม่ได้ จึงไม่ลบข้อมูลภาษีบนคลาวด์โดยไม่ตั้งใจ
- ถ้าสองเครื่องตั้งเงินเดือนหรือประกันสังคมเดือนเดียวกันแยกกัน ยอดที่เท่ากันจะรวมเป็นรายการเดียว ยอดต่างกันจะให้เลือกเก็บข้อมูลฝั่งใด รายได้ที่เกิดจากรายการรายรับรายจ่ายที่ติ๊กนับภาษี แต่ละเครื่องสร้างเองจากรายการนั้น ไม่ซิงก์ซ้ำ หากเครื่องหนึ่งมีเงินเดือนเดือนนั้นจากรายการรายรับรายจ่ายอยู่แล้ว เงินเดือนที่กรอกตรงในภาษีของเดือนเดียวกันจะถูกแทนที่ด้วยรายการนั้น ชุดกฎปัจจุบันรองรับปี 2025/2026
- ออฟไลน์เก็บข้อมูลใน IndexedDB ของเบราว์เซอร์และ SQLite ในคอม ล้างข้อมูลเว็บไซต์ ถอนติดตั้ง หรือใช้งานโหมดส่วนตัวอาจทำให้รายการที่ยังไม่ส่งหายได้ สำรองข้อมูลจากคอมเป็นไฟล์เข้ารหัสได้ตามเดิม
- ข้อมูลออนไลน์ส่งผ่าน HTTPS และอ่านได้เฉพาะบัญชีเจ้าของผ่าน RLS แต่ไม่ได้เข้ารหัสแบบปลายทางถึงปลายทาง ผู้ดูแลโปรเจกต์ Supabase อ่านข้อมูลได้ session เข้าระบบเก็บในเครื่อง ไม่อยู่ในไฟล์สำรองภาษี
- การกู้คืนไฟล์สำรองหรือ **ลบข้อมูลในแอป** เป็นการทำในเครื่องและพักซิงก์ ไม่ลบสำเนาออนไลน์ เมื่อเริ่มซิงก์อีกครั้ง ระบบรวมข้อมูลที่กู้คืนกับข้อมูลออนไลน์ บัญชีซิงก์เดิมยังผูกกับฐานข้อมูลในเครื่องเพื่อป้องกันข้อมูลของหลายบัญชีปะปน
- **พักการซิงก์** หยุดส่ง/รับชั่วคราว **ออกจากระบบ** ลบ session บนเครื่องนั้น แต่ยังเก็บสำเนาข้อมูลในเครื่องตามปกติ ถ้าต้องการเปลี่ยนบัญชีสำหรับฐานข้อมูลคอม ให้ใช้ฐานข้อมูลคนละชุด ไม่ย้ายข้อมูลให้อัตโนมัติ

## วิธีซิงก์และการทดสอบ

แต่ละบัญชีมี snapshot พร้อม revision บนเซิร์ฟเวอร์ แอปบันทึกรายการส่งลงดิสก์ก่อนส่ง และใช้ UUID เป็นใบรับการส่งซ้ำ เซิร์ฟเวอร์ผูก UUID กับ hash ของข้อมูลและ revision ที่คาดไว้ การส่งสำเร็จแต่คำตอบหายจึงส่งซ้ำได้โดยไม่เขียนซ้ำ และการลบ/แก้ระหว่างส่งยังคงอยู่ หลังส่งแล้วรวมการเปลี่ยนแปลงจากสามชุด: ข้อมูลที่เคยตรงกัน ข้อมูลในเครื่อง และข้อมูลออนไลน์ ไม่ตัดสินรายการที่แก้ชนกันโดยดูนาฬิกาของอุปกรณ์

Realtime แจ้งเฉพาะ revision ของบัญชีนั้น แล้วแอปอ่าน snapshot ผ่านสิทธิ์บัญชี มีการตรวจซ้ำเมื่อกลับมาออนไลน์ เปิดหน้าแอป และทุก 30 วินาที เผื่อการเชื่อมต่อสดหลุด เวอร์ชันนี้ใช้ทั้ง snapshot จำกัด 20 MiB, 1,000 หมวดหมู่ และ 200,000 รายการต่อบัญชี จึงเหมาะกับบัญชีส่วนตัว ไม่ใช่ระบบบัญชีองค์กรขนาดใหญ่

รันการทดสอบจาก `apps/desktop`:

```sh
npm test
npm run test:e2e
npm run build
TAXLY_E2E_PREVIEW=1 npx playwright test e2e/mobile-sync.spec.ts
```

สอง browser context ใช้บัญชีสังเคราะห์กับ API/WebSocket จำลองและ IndexedDB จริง การเปิดออฟไลน์ทดสอบกับ production service worker จริง ส่วน RLS, RPC, การส่งซ้ำและ revision ทดสอบกับ PostgreSQL แยก ไม่ใช่หลักฐานของการ deploy Supabase จริง ต้องทดสอบบัญชีจริงสองอุปกรณ์หลังสร้างบริการและโฮสต์แล้ว

จากรากโปรเจกต์ รัน `scripts/test-ledger-sync-sql.sh` เพื่อสร้าง PostgreSQL ชั่วคราวผ่าน Unix socket และตรวจ SQL/RLS โดยไม่แตะบริการจริง ต้องติดตั้ง server tools ก่อน ใช้ `PG_BIN=/path/to/postgres/bin` หากไม่ได้ติดตั้ง PostgreSQL 17 ผ่าน Homebrew
