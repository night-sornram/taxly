# User Flows และ Onboarding

เริ่มต้น -> รู้จักคุณ -> เงินเดือน -> ยืนยันเดือนจริง/เครดิต -> โบนัส -> ประกันสังคม -> สิทธิ์อื่น -> ตรวจสรุป

ทุกครั้งที่เปลี่ยนขั้น บันทึก draft ผ่าน Rust/SQLite ขั้นที่ยังไม่เสร็จไม่ได้ถูกนับเป็นรายการรายได้จนกดยืนยันสุดท้าย ซึ่งสร้าง records ใน transaction เดียว

ตัวเลขเริ่มว่าง ไม่เติมเงินเดือนหรือเพดานสมทบเอง ผู้ใช้เลือก actual-through; เดือนที่เหลือเป็น forecast แม้เป็นเดือนที่ผ่านมาแต่ยังไม่ยืนยัน

Bonus ว่างหมายถึงยังไม่ระบุ หากยืนยันครบปีต้องระบุจำนวนหรือ 0 ชัดเจน Withholding ว่างหมายถึง unknown และต่างจาก 0 เสมอ การใช้ยอดหักเดียวกันประมาณเดือนอนาคตต้องเลือกเอง

เปลี่ยน forecast เป็น actual ด้วยการแก้ record เดิม ไม่มีการสร้างรายการอีกชุด โบนัสหลายครั้งแยก ID; ยืนยัน bonus เดิมก่อนเพิ่มเงินจริงเพื่อไม่ซ้ำ

รายการเงินสมทบเป็นยอดรวมฝ่ายลูกจ้างจากทุกนายจ้างต่อเดือน แก้แยกเดือนเมื่ออัตราหรือจำนวนจริงต่างกัน

Deduction Assistant แสดงสิทธิ์/เงื่อนไข/หลักฐาน/แหล่งกฎ เฉพาะสิทธิ์ที่รองรับจึงแสดงวงเงินหรือ savings โดยคำนวณทั้งชุดใหม่ก่อน/หลังใช้สิทธิ์
